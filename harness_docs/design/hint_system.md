# 힌트·열쇠·클리어 보상 시스템 설계 계약

상태: 구현 완료·최종 릴리스 QA 진행 중. 이 문서는 현재 코드와 테스트가 지키는 제품 계약이다. 최종 Web 배포·실기기 범위·영상 산출물의 통과 여부는 릴리스 QA 문서에서 별도로 판정하며, 레퍼런스의 출처와 비복제 한계는 [UI·힌트·시연 난이도 레퍼런스 조사](../qa/ui_hint_reference_research.md)를 따른다.

## 목표

- 작은 모바일에서도 클리어 보상 선택과 다음 행동이 가려지지 않게 한다.
- 보상에서 선택한 다음 스테이지 팁은 실제로 그 스테이지에서 사용할 수 있고, 기믹 사용법을 구체적으로 알려 준다.
- 열쇠 접촉은 클리어와 독립적으로 팁 열람 권한을 준다.
- 시연 스테이지는 기믹을 생략한 직선 발사로 끝나지 않게 한다.

## 화면 계약

### HUD 및 파워 게이지

- 게임 월드는 풀블리드 렌더링을 허용한다.
- `SafeArea` 적용 뒤 `LayoutBuilder`의 실제 제약으로 상단·중앙·하단 HUD 밴드를 배치한다. 기기명·세로/가로 값 자체로 화면을 고정 분기하지 않는다.
- 파워 게이지는 중앙 쪽의 부유 레이어에 두되, 홀 입구·발사선·공의 첫 충돌 지점을 가리지 않는다. 충전 상태는 색상만으로 전달하지 않고 단계명/링/눈금 등 보조 표시를 둔다.
- HUD는 Flame 월드 좌표와 분리한다. 게임 기물은 월드에, 가시성·터치·안전 영역 책임이 있는 HUD는 카메라/Flutter 오버레이에 둔다.

### 클리어 팝업

- 일반 높이: 클리어 결과, 핵심 점수, 보상 선택, 다음 CTA 순이다.
- compact 높이: **보상 선택을 점수 세부보다 먼저** 보여 준다. 점수 세부와 부가 설명은 접거나 스크롤하며, 팝업 하단의 다음 CTA는 안전 영역 안 footer에 고정한다.
- 상태 변화는 짧은 fade만 사용한다. 저모션에서는 fade 시간을 0으로 하거나 정적 교체로 대체한다.
- 보상 카드에는 ‘다음 스테이지 클리어 팁’ 선택지를 제공한다. 선택·잠금 해제·이미 사용 상태가 문구와 아이콘만이 아니라 Semantics 라벨에도 반영되어야 한다.

## 열쇠와 팁 권한

### 열쇠 계약

- 열쇠는 스테이지의 승패·물리·점수에 영향을 주지 않는 비물리 수집물이다. 공이 정의된 접촉 반경에 진입하면 즉시 수집되며, 같은 시도에서 중복 수집되지 않는다.
- 판정은 프레임 타이밍·카메라 위치·무작위성에 의존하지 않는 결정론적 규칙이어야 한다.
- 열쇠는 홀까지 가는 필수선 위일 필요가 없지만, 화면에서 식별 가능하고 정상 조작으로 1~2회 시도 안에 도달 가능한 위치에 둔다. 막다른 구석·가림막 뒤·과도한 정밀 조준 요구 위치는 금지한다.
- 수집 시 ‘다음 스테이지 팁 해금’이라는 즉시 피드백을 주고, 시각 외에도 한글 텍스트 및 저모션 대응을 제공한다.

### 권한 및 저장

- `RunState v3`는 저장본 버전, 열쇠 수집 기록, `stageId + patternId + hintVersion` 권한, 열람 단계, 실패 누계와 최초 열람 시점 기준값을 보존한다. v1·v2 저장본은 명시적으로 v3로 마이그레이션하며 과거 L3 값은 현재 L1·L2 계약에 맞춰 L2로 낮춘다.
- 권한은 현재 실행에서만 보이지 않게 사라지지 않고 앱 재시작 뒤에도 복원되어야 한다. 저장 실패/구버전 복원 시에는 중복 보상·잠금 해제 손실·크래시 없이 보수적 기본값으로 처리한다.
- 저장되는 값은 게임 진행을 위한 최소 식별자만이다. 계정·위치·개인정보 및 외부 전송은 이 계약의 범위 밖이다.

## HintCatalog v1

- 데이터는 버전이 있는 `HintCatalog`로 제공하며 초기 범위는 40개 패턴이다.
- 각 패턴에는 `stageId`, `patternId`, `hintVersion`, 기믹·대상 ID, 의도와 로컬라이즈된 L1·L2 텍스트를 둔다. Validator는 40개 패턴의 누락·중복·잘못된 대상·L3·정답 숫자 노출·추상 문구를 안정 오류 코드로 거부한다.
- 힌트는 다음의 검증 가능한 형식을 사용한다.

  `기믹/대상 → 조준 위치·세기 → 행동 순서 → 공의 예상 경로/결과`

- 금지 문구: “잘 튕겨 보세요”, “타이밍을 맞추세요”, “기믹을 활용하세요”처럼 행동을 결정할 수 없는 표현.
- 예시(구조 예시이며 특정 스테이지 수치 확정 아님): “왼쪽 아래 스프링의 중앙을 중간 세기로 맞히세요. 공이 위로 뜨면 세로 반사판의 왼쪽 면을 지나 홀 입구 오른쪽으로 꺾입니다.”
- 카탈로그 버전이 바뀌면 과거 `id`의 의미를 재사용하지 않는다. 삭제된 패턴은 호환용 별칭 또는 안전한 미표시 정책을 명시하고, 저장된 열람 권한은 보존한다.

## `bouncy_01` 시연 계획

1. 시작 화면에서 중앙 부유 파워 게이지와 열쇠를 동시에 읽을 수 있게 잡는다.
2. 열쇠는 핵심 클리어선 밖의 접근 가능한 위치에 둔다. 공 접촉 뒤 팁 해금 피드백을 한 번 보여 준다.
3. 직선 발사선은 홀에 닿지 않거나 유효 포획 조건을 충족하지 않아야 한다.
4. 성공 경로는 오른쪽 아래 젤리에서 탄성을 공으로 이전한 뒤, 검증된 48도·90% 시연 입력으로 세 번 이상의 벽 반사를 거쳐 홀에 들어간다. 젤리 직접 충돌을 주장하지 않고 `탄성 이전 + 다중 벽 반사`로 설명한다.
5. 클리어 뒤 compact 보상 화면에서 ‘다음 스테이지 클리어 팁’을 선택하고, 다음 스테이지에서 동일한 힌트를 열어 구체 행동을 확인한다.

## 접근성·성능·검증 조건

- 모든 새 컨트롤과 열쇠/힌트 상태에 화면 읽기 한글 라벨, 색상 외 상태 구분, 충분한 터치 영역, 키보드/포인터 기본 접근성을 제공한다.
- 저모션에서 필수 정보와 상태 변화는 유지하되 반복 펄스·과한 이동을 제거한다.
- 팝업 스크롤·HUD·열쇠 효과는 매 프레임 불필요한 전체 재빌드를 피하고, HintCatalog은 한 번 검증·캐시하며, 수집 판정은 상수 시간에 가깝게 유지한다.
- 최종 통과 기준은 320×568·375×812·390×844·430×932·768×1024·1024×1366과 웹 리사이즈에서 CTA 가림 없음, Dynamic Type/화면 읽기/저모션, 저장 마이그레이션, 열쇠 결정성, `bouncy_01` 직선 실패·기믹 성공, 성능 측정 및 회귀 테스트다.
- 위 뷰포트 Golden, 열쇠 저장 지연 중 애니메이션 비차단, L1→L2, v1/v2→v3 마이그레이션, 다음 패턴 권한 결속, 일일 도전 보상 제외, 결정론 열쇠 순서와 시연 계약은 자동 테스트 대상이다. 실제 기기·릴리스 Web 성능과 최종 영상은 별도 근거가 생기기 전까지 미검증으로 남긴다.
