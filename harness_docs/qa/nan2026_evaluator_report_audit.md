# NAN 2026 평가관 관점 보고서 감사

작성일: 2026-08-10

## 조사 범위

NAN 2026 공식 안내와 공개 게임잼·AI 해커톤 평가 자료를 읽고, 게임 소개·AI 활용 기술 문서·포트폴리오를 평가자가 짧은 시간 안에 이해할 수 있는지 검토했다. 공개 배점표가 없으므로 보조 자료의 항목을 NAN의 공식 기준으로 주장하지 않는다.

## 참고 자료

- [NAN 2026 공식 안내](https://nan2026.nhn.com/): AI를 활용한 게임 제작, AI 디렉팅 문제의식, 발표·시연 맥락
- [Federal AI Hackathon judging](https://gsa-stg-ecas.gsa.gov/technology/government-it-initiatives/federal-ai-hackathon/the-judging): 문제·혁신·기술·사용자 경험·책임 있는 AI 관점
- [Taylor University GameJam judging](https://gamejam.cse.taylor.edu/judging.php): 혁신성·게임플레이·프로그래밍·그래픽·오디오·완성도
- [BCI Game Jam 2026](https://bci.games/jams/2026): 창의성·접근성·재미·플레이 용이성·재플레이성
- [IxDF case-study guide](https://ixdf.org/literature/article/how-to-write-great-case-studies-for-your-ux-design-portfolio): 결과보다 문제·과정·판단·증거를 연결하는 포트폴리오 서사
- [Hack n Hoard · Devpost](https://devpost.com/software/hack-n-hoard): Inspiration, What it does, How we built it, Accomplishments, What we learned 순서의 실제 해커톤 프로젝트 서사
- [PRESS PLAY submission guide](https://pressplay-cub.com/submissions): 게임 설명 자료에서 제목, 핵심 메커니즘, 조작, 사용 소프트웨어를 명확히 분리하는 구성
- [Game Developer postmortem analysis](https://media.gdcvault.com/GD_Mag_Archives/GDM_February_2011.pdf): 프로젝트 회고를 잘된 점과 어려웠던 점처럼 구체적 경험 단위로 정리하는 형식

## 도출한 평가 관점

1. 첫 30초 안에 게임의 한 줄 가치와 실제 화면이 보이는가.
2. 플레이어의 목표·조작·진행·실패 후 행동을 이해할 수 있는가.
3. 일반 물리 조준 게임과 다른 규칙이 명확한가.
4. 10단계 학습 곡선과 주요 지원 기능이 플레이 가치로 설명되는가.
5. AI 프롬프트가 실제 작업·결정·검증 결과와 연결되는가.
6. 사람이 재미와 정책을 결정하고 AI 결과를 반려·감사한 과정이 보이는가.
7. 수치와 기술 근거가 과장 없이 사용자 경험을 뒷받침하는가.

## 반영한 변경

- 표지의 커밋 ID와 저장소 주소를 제거하고 실제 플레이 hero를 배치했다.
- 게임 문서 전면을 한 줄 가치, 플레이 루프, 학습 곡선, 주요 기능, 차별점 순으로 재구성했다.
- 실행·빌드·검증은 후반으로 이동하고 해시·워크플로 번호를 본문에서 제거했다.
- AI 문서에 실제 프롬프트 발췌와 제약→작업→결과→검증 표를 추가했다.
- 사람·실행 에이전트·독립 감사 에이전트·이미지 생성 도구의 역할을 분리했다.
- 잘못된 기믹 우위 지표를 독립 감사로 반려한 사례를 핵심 AI 디렉팅 증거로 제시했다.
- 포트폴리오는 문제→의사결정→전후 결과→개인 기여→회고의 사례 연구로 신규 제작했다.
- 평가 기준을 평가자에게 설명하는 메타 문단은 최종 보고서에서 제거하고 이 내부 감사 문서에만 보존했다.
- 해커톤 프로젝트 페이지의 간결한 서사를 참고해 `출발점 → 게임이 하는 일 → 제작 과정 → 주요 결정 → 결과` 순으로 바꾸고 표 중심 문장을 회고형 문장으로 줄였다.
- 제작 과정은 사용자 피드백 → 기능 계약 → 전문 실행 → 독립 감사 → 증거·통합의 편집 가능한 관계도로 표현했다.
- AI 기술 문서 앞부분에 사람의 결정, AI 실행, 독립 AI 감사의 역할을 관계도와 작업별 표로 분리했다.
- 서로 다른 표본공간 비교, 접근성 과잉 알림, 완료 난이도 귀속 오염을 `AI가 틀렸고 검증이 잡은 사례`로 전면 배치했다.
- StagePatternValidator를 정적 검사 → 물리 탐색 → 결정론 반복 → invalid fixture 역검증 → 게임 등록 흐름으로 승격하고, 검증 도구 자체의 탐지 능력도 시험했다는 점을 명시했다.
- 포트폴리오의 기존 UX 개선 문장을 `문제 → 판단 → 결과` 증거 구조로 바꾸고, 중복 설명 대신 Validator 사례 연구와 선택 참고자료 색인을 추가했다.

## 최종 감사 기준

- 게임 소개: 첫 2쪽에서 장르·차별점·플레이 방법·완성 범위를 이해할 수 있어야 한다.
- AI 기술: 실제 프롬프트, 인간 결정, AI 작업, 반려·검증이 최소 4개 사례로 연결되어야 한다.
- 포트폴리오: 완성 화면 나열이 아니라 문제 해결과 개인 기여가 드러나야 한다.
- PDF: A4, 빈 페이지·잘림·겹침·한글 깨짐이 없어야 한다.
- PPT: A4 세로, 모든 본문과 표·이미지가 개별 편집 가능한 객체여야 한다.
