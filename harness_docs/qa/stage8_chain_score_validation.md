# PS-STAGE-05 8단계 창의 연쇄 점수 검증

기준일: 2026-08-07 KST

## 원문 프롬프트 요약

- 8단계 `세 번 이어라`에서 최소 샷과 높은 연쇄 점수 전략의 차이를 배운다.
- 벽, 과거 공, 상자, 돌, 젤리, 풍선, 파워 슬라이더, 스위치, 문 중 패턴마다 5~6종을 사용한다.
- 3쿠션, 벽에서 상자와 과거 공으로 이어지는 경로, 파워 슬라이더에서 돌·벽·공으로 이어지는 경로, 직선 저점수와 연쇄 고점수의 병존을 제공한다.
- 특정 기믹을 필수로 만들지 않고 모든 패턴에 직접 또는 우회 풀이를 남긴다.
- 최종 홀에 실제로 기여한 연쇄만 설명하며 반복 충돌 점수 파밍을 막고 같은 리플레이가 같은 점수를 재현해야 한다.
- 한글 UI, 벽 불변, 과거 공 유지, 기본 홀 성공 조건을 지킨다.

## 구현 결과 요약

- 단계 ID와 제목: `stage_chain_score`, `8. 세 번 이어라`
- 패턴: `stage_chain_score_01`~`04`, 기준 패턴은 1번이다. 실제 진입 시 스테이지별 셔플 백으로 추첨하고 진행 중인 `patternId`와 `patternSeed`를 A/B `RunState`에 저장한다. 다음 단계 패턴은 클리어 직후 팝업보다 먼저 선추첨·저장하고 `다음` 진입 때 새로 뽑지 않고 활성화한다.
- 네 패턴 모두 `acceptedStrategyIds`에 `none`을 포함하고 직접 클리어 경로와 고연쇄 경로를 함께 제공한다.
- 클리어 팝업은 `CreativeChainScoreAnalyzer` 결과의 총점과 모든 가산 근거를 한글로 표시한다.
- 발사 결과 목록은 단계별로 보존하며 재시작과 되감기 때 함께 초기화하거나 한 발 되돌린다.
- 속성 이전·복사는 실제 화면에 적용하기 전에 순서대로 즉시 저장하고 한 샷에 여러 행동이 있어도 모두 보존한다. 각 샷의 패턴 seed, 논리 각도, 힘, 장착 속성과 행동 목록을 발사 전에 저장하며 앱 재실행 시 `ShotResolver`로 재생해 원본 속성, 복제 코어, 과거 공과 이동 기물까지 복원한다.
- 클리어 시 RunState 완료와 다음 패턴 선추첨을 먼저 원자 저장하고 지도 해금·개인 기록을 저장한 뒤에만 클리어 팝업을 연다.
- 성공 샷 로그 저장 뒤 완료 저장 전에 종료된 경우 재실행 시 샷을 다시 계산해 성공을 확인하고 런 완료·다음 패턴·지도 기록을 복구한다. 복제 코어의 기준 저장소는 `RunState` 하나이며 되감기와 재시작의 환급도 같은 기록에서 계산한다. 스테이지 보상은 `stage_clone_core:<stageId>` 획득 표식과 수량을 함께 저장해 종료 경계에서도 누락되거나 중복 지급되지 않는다.
- 포인터 조준은 1도 단위 논리 각도로 확정해 화면 해상도와 픽셀 흔들림이 리플레이 입력을 바꾸지 않게 한다.
- 8단계의 높은 연쇄는 선택 추가 도전이며 기본 클리어 판정을 변경하지 않는다.
- 패턴별 추가 도전은 전체 사건 나열이 아니라 최종 홀 포획의 부모 계보에 포함된 사건 종류와 순서로 판정한다. 과거 공 포획은 `hole impact`와 `hole_captured` 이동 표현을 모두 인정한다.

모든 힘은 실제 UI 최소 힘 12% 이상이며 2% 눈금에 정렬했다.

| 패턴 | 준비 발사 | 최종 발사 | 실제 인과 계보 요약 | 연쇄 점수 | 직접 경로 |
|---|---:|---:|---|---:|---:|
| 1 4쿠션 | 160도 / 20% | 158도 / 96% | 왼쪽 벽 → 아래 쿠션 → 과거 공 → 왼쪽 쿠션 → 아래 쿠션 → 발판 → 홀 | 1970 | 324도 / 12%, 1035점 |
| 2 상자 연쇄 | 340도 / 92% | 236도 / 76% | 왼쪽 벽 → 상자 이동 → 과거 공 → 홀 | 1689 | 266도 / 20%, 1035점 |
| 3 발판·돌·벽 | 280도 / 42% | 312도 / 84% | 발판 → 돌 → 수평 쿠션 → 오른쪽·위쪽 벽 → 과거 공 → 홀 | 2002 | 266도 / 32%, 1035점 |

점수는 선택 도전 전체를 활성화한 분석 결과다. 직접 경로는 인과 깊이 0, 과거 공 0개이며 홀 기본점과 최소 샷 보너스만 받는다.

1번 패턴은 첫 공을 폭 32의 점착 받침에 안정적으로 남긴다. 과거 공만 히트박스를 1.0으로 키우던 비일관성을 제거한 뒤 기존 22도 경로를 폐기하고, 왼쪽·아래 쿠션을 거쳐 점착판에 도달하는 160도 준비 경로를 다시 탐색했다. 현재 경로는 248개 성공점과 63개 최대 연결 영역을 확보했으며 첫째 3개, 둘째 4개의 연속 1도 구간을 가진다.

## 입력 허용 영역

직접 경로는 전체 2도·2% 격자 8,100개, 고연쇄는 대표 입력 주변 각 발 ±4도·±8%를 각도 1도·힘 2% 간격의 4차원 격자로 실제 `ShotResolver`에 입력했다. 포인터 입력도 같은 1도 논리 구간으로 확정한다.

| 패턴 | 직접 성공 / 최대 연결 | 고연쇄 성공 / 최대 연결 | 유효 첫째 발 | 유효 둘째 발 |
|---|---:|---:|---:|---:|
| 1 | 2,265 / 627 | 248 / 63 | 38 | 31 |
| 2 | 1,207 / 712 | 485 / 458 | 20 | 63 |
| 3 | 868 / 507 | 704 / 704 | 42 | 36 |
| 4 | 610 / 222 | 375 / 231 | 26 | 39 |

모든 패턴은 직접 경로 최대 연결 영역 100개 이상, 고연쇄 연결 영역 5개 이상, 첫째·둘째 발 유효 입력 각각 3개 이상을 유지한다. 각도 구간은 떨어져 있는 성공점의 최솟값과 최댓값 차이가 아니라 실제 성공 각도 인덱스의 가장 긴 연속 구간만 센다. 패턴별 첫째·둘째 연속 구간은 3·4개, 5·6개, 6·4개, 6·5개로 한 각도만 요구하던 정밀도 위험을 제거했다.

## 파밍 방지 계약

- 같은 접촉은 0.25배, 같은 벽면 반복은 최대 0.2배로 감쇠한다.
- 미세 진동은 점수와 인과 깊이에서 제외한다.
- 인과 충돌은 최대 12건, 인과 사슬 밖 충돌은 최대 3건만 반영한다.
- 같은 과거 공, 파워 슬라이더, 판 상태 변화는 전용 보너스를 중복해서 받지 않는다.
- 준비 발사는 최종 홀 사건 계보에 남은 공이나 이동 상태가 실제로 기여할 때만 인정한다.
- 네 대표 해법은 `qualifiedImpactCount <= 12`와 동일 입력의 점수 서명 일치를 검증한다.

## 자동 검증 현황

완료:

- `dart run tool/generate_stage_catalog.dart`: JSON 정적 배치와 생성 카탈로그 동기화 통과
- `tool/stage8_solution_search.dart`: 직접·고연쇄 해법과 실제 사건 위치 탐색 완료
- 네 대표 입력의 인과 사건 종류·순서와 패턴별 추가 도전 재현 완료
- `stage8_chain_score_fixtures.json`: 네 패턴의 직접·고연쇄 공식 리플레이 8개와 물리 지문·점수·서명·Breakdown 동기화 통과. 반복 fingerprint, 유한 벡터, 안전 중단 부재, 벽 불변, ID 중복 부재, 모든 샷 종료 겹침, 필드 이탈, 슬라이더 포함 고속 터널링, 홀 포획 후 후속 충돌과 최종 성공을 함께 검증한다. 총 612개 이동 선분과 23개 터널링 후보가 대응 사건을 가진다. 네 고연쇄 준비 샷의 결과 상태에서 실제 다음 대표 입력을 다시 계산해 저장된 둘째 결과 지문·유한값·샷 순서·안전 중단 부재가 일치할 때만 소프트락 없음으로 인정한다.
- 클리어 런 저장이 실패하면 클리어 팝업·보상·다음 단계 이동을 열지 않는다. 일반 발사 실패의 되감기·초기화도 노출하지 않고 같은 저장 트랜잭션만 다시 시도한다. 런 완료 뒤 진행 저장 전에 종료한 경우 앱 시작 시 지도 해금·최고 샷·보너스 기록을 멱등 복구한다.
- 저장 경계는 `Exception`뿐 아니라 `RunStateStore`와 검증 로직이 사용하는 `StateError`도 처리해 발사·속성 행동·클리어·보상 실패 후 입력 잠금을 해제한다. `SharedPreferences`의 `set`·`remove`가 예외 없이 `false`를 반환하는 경우도 저장 실패로 바꿔 재시도 흐름에 전달한다.
- 성공 샷 저장 뒤 런 완료 전에 종료한 경우 1~7단계는 저장된 샷의 범퍼·스위치·비워진 원본 이동을 다시 계산하고, 8단계는 창의 연쇄 분석을 다시 계산해 완료 상태와 보너스를 복구한다. 재실행 뒤 되감기에 필요한 샷별 누적 보너스 이력도 같은 결과 목록에서 재구성한다.
- 복제 코어는 `RunState`의 수량과 `stage_clone_core:<stageId>` 획득 표식만 기준으로 삼는다. `ProgressStore` 스키마 3도 지급 단계 ID 집합을 함께 미러링하며 전역 지급 불리언은 구형 호환에만 사용한다. 지급 여부는 현재 단계 ID로 판정해 향후 보상 단계가 늘어나도 서로 막지 않는다. RunState가 없는 구형 진행도와 중간 버전의 `stage_clone_core:legacy` 표식은 수량을 늘리지 않고 실제 과거 보상 단계인 `stage_chain_gate` 표식으로 원자 마이그레이션한다.
- `patternSeed`가 없는 구형 현재 샷은 로그 끝의 연속 접미 구간이고 같은 패턴의 추첨 이력이 하나뿐일 때만 현재 seed를 채워 원자 저장한다. 같은 패턴이 여러 셔플 주기에 등장해 소속을 확정할 수 없으면 현재 주기에 임의 결합하지 않고 복원하지 못한 발사가 있음을 한글로 알린다. 이 경우 복사 행동을 추정 재생하거나 임의 환급하지 않고 저장된 복제 코어 수량을 그대로 유지해 과거 사용분의 중복 지급을 막는다.
- 정상 seed 샷과 소속이 모호한 구형 샷이 함께 있어도 확인 가능한 발사 수와 제외 사실을 우선 안내한다. 독립 게임 화면의 다음 단계 요청과 개발 진단의 진행 초기화·전체 해금·코어 설정도 저장 실패를 처리하며 저장 성공 전 화면 상태를 바꾸지 않는다.
- 기기 시계가 뒤로 조정되거나 미래 시각의 저장을 복원해도 `updatedAt`은 기존 저장 시각보다 뒤로 가지 않는다. 저장 런 복구·보상 지급·구형 마이그레이션이 날짜 검증에 막히지 않는 회귀를 고정했다.
- 발사 뒤 남는 과거 공은 발사 전 공의 `hitboxScale`을 그대로 이어받는다. 같은 외형의 공이 과거 공이 됐다는 이유만으로 충돌 반경이 커지지 않으며, 7단계 대표 쿠션 경로와 8단계 공식 경로를 함께 재검증한다.
- `stage8_solution_regions.json`: 정적·런타임 Validator 이슈 0건과 직접·고연쇄 성공 영역 동기화 통과

- 외부 Flutter 게이트 이후 독립 Luna 재감사: 최초 P1이던 저장 전 메모리 해금과 P2였던 README 단계 수·결과 팝업 Golden 범위를 보정했다. 지도 저장 첫 실패 시 `1 / 8`을 유지하고 재시도 성공 뒤에만 2단계가 열리는 실제 라우터 회귀를 확인했다. 후속 한글 UI 감사의 개발 진단 영문 약어도 `물체 식별자`·`상태 데이터`로 교정해 P0·P1·P2 미해결 항목 없음

별도 Chromium 콘솔 감사와 실제 기기 터치 입력의 초보 사용자 발견률 측정은 10단계 통합 데모 게이트에서 수행한다. 이 두 항목은 8단계 결정론·저장·Golden 승인과 분리된 Web 보조 검증 및 사용자 조사 항목이다.

## 잔여 위험

- 최고 연쇄 점수와 최소 샷 수는 A/B `RunState`에 보존하지만, 별도 기록 화면과 실제 사용자 순위 비교는 후속 보상·리플레이 작업 범위다.
- 긴 점수 근거 목록은 세 화면 크기와 1.5배 글자 크기에서 실제 마지막 항목까지 스크롤됨을 확인했고, 결과 팝업 자체도 5해상도 Golden으로 고정했다.
- 대표 자동 입력 영역은 충분히 연결되어 있지만 일반 사용자가 연쇄 경로의 시각적 단서를 스스로 읽는지는 수동 플레이테스트가 필요하다.
- 일반 사용자가 직접 경로와 고연쇄 경로의 차이를 설명 없이 발견하는지는 사용자 플레이테스트가 필요하다.
