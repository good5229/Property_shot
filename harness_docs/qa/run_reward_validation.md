# PS-REWARD-01: 결정론 런 보상 검증

## 원문 프롬프트 요약

9단계 이후 개발은 열 단계의 물리 퍼즐을 한 번의 런으로 연결하고, 단계 클리어 뒤 세 후보 중 하나를 고르는 보상 흐름을 추가하는 작업이다. 보상은 특정 기믹을 필수 정답으로 만들거나 결정론적 물리 결과를 임의로 바꾸지 않아야 한다. 후보·선택·사용은 앱 종료, 재실행, 되감기, 재도전에서도 중복 지급되거나 되살아나지 않아야 하며 모든 화면 문구는 한글이어야 한다. 마지막 단계 뒤에는 새 런 시작과 메인 메뉴 이동이 가능한 결과 화면이 필요하다.

## 구현 결과 요약

- 런 루트 seed, 안정 단계 ID, 현재 패턴 seed로 보상 세 개를 결정론적으로 생성한다.
- 단계 클리어 뒤 보상을 선택하기 전에는 다음 단계와 기록 재도전을 잠근다.
- `run_reward:<stageId>:<patternSeed>:<rewardId>` 선택 기록을 저장해 같은 패턴 재도전에서 기존 선택을 복원하고 보상을 다시 지급하지 않는다.
- 일회성 사용은 선택 기록별 `run_reward_used` 표식으로, 단계별 사용은 `run_reward_stage_used` 표식으로 분리한다.
- 마지막 단계의 보상 선택 뒤 `runCompleted`를 저장하고 총 연쇄 점수, 단계별 최고 기록 합계, 선택 보상 수를 한글 결과 화면에 표시한다. 새 런은 새 루트 seed와 새 셔플 백에서 시작한다.

## 보상별 실제 효과

| 보상 | 실제 플레이 효과 | 저장 단위 |
| --- | --- | --- |
| 복제 코어 1개 | 원본 속성을 유지하는 복사 횟수 1회 추가 | 선택 즉시 영구 반영 |
| 발사 취소 보조 1회 | 충전 중 취소 버튼으로 발사를 중단하고 시도 수를 늘리지 않음 | 선택 기록당 1회 |
| 과거 공 1회 회수 | 실패 팝업에서 최근 과거 공 하나를 필드에서 제거 | 선택 기록당 1회, 단계·공 ID 복원 |
| 첫 충돌 대상 표시 1회 | 조준 중 예상 궤적 없이 첫 충돌 대상 이름만 표시 | 다음 실제 발사 때 1회 |
| 선택 도전 실패 1회 무효화 | 클리어했지만 선택 도전을 놓친 경우 달성으로 저장 | 선택 기록당 1회 |
| 실패 인과 표시 강화 | 실패 팝업에 실제 충돌 대상 순서를 최대 5개까지 표시 | 보유한 런 동안 유지 |
| 청록 유광 공 꾸미기 | 공 본체 재질, 청록·금빛 이중 테두리, 하이라이트, 미세 파티클과 발사 잔상을 변경. 크기·물리·히트박스는 불변 | 보유한 런 동안 유지 |
| 스테이지 기록 보호 | 단계마다 한 번 클리어 발사 횟수를 1회 줄여 기록 | 보상 선택별 단계당 1회 |

과거 공 회수는 `stageId|stageAttempt|spentBallId`를 사용 기록에 남긴다. 재도전과 되감기마다 단계 시도 번호를 단조 증가시켜 이전 시도에서 회수한 공과 같은 번호로 새로 생성된 공을 구분한다. 저장 샷을 재생한 뒤 현재 시도에서 회수된 공만 다시 제거하므로 앱 재실행이나 되감기로 공이 되살아나거나 새 공이 잘못 사라지지 않는다. 첫 충돌 안내는 `ShotResolver`의 현재 방향·힘 계산을 읽기 전용으로 사용하고 선이나 충돌 지점을 그리지 않는다.

## UI와 접근성

- 보상 이름·설명·오류·완료·결과 화면은 모두 한글이다.
- 보상 후보 버튼은 이름과 설명을 줄임표 없이 여러 줄로 표시한다.
- 320×700, 390×844, 390×844 큰 글자 1.3배, 768×1024 Golden으로 8종 설명을 나누어 확인한다.
- 발사 취소와 과거 공 회수는 해당 행동이 가능한 순간에만 아이콘과 한글 도움말을 표시한다.
- 첫 충돌 안내는 최종 경로와 충돌 여부를 선으로 노출하지 않고 대상 이름만 표시한다.
- 공 꾸미기는 선택 전에 시각 전용 보상이며 물리 성능과 판정은 변하지 않는다고 명시한다. 모션 감소에서는 파티클 회전·맥동을 멈추고 고정된 세 점만 남긴다.
- 생성 공 스프라이트를 실제로 불러온 390×844, 768×1024, 1440×900 Golden과 52·76·108px 비교 Golden으로 본체·테두리·하이라이트 식별성을 확인한다.

## 자동 검증

- 보상 카탈로그 8종의 안정 ID, 한글 메타데이터, JSON 왕복을 검증한다.
- 후보는 같은 세 seed에서 같은 순서를 유지하고 항상 중복 없는 세 개이며, 여러 seed에서 조합이 달라진다.
- 선택 저장 실패는 같은 후보를 유지하며, 보상 선택 전 다음 단계 이동을 거부한다.
- 일회성 사용은 두 번째 호출을 거부하고 재실행 뒤에도 소모 상태를 유지한다.
- 단계별 사용은 같은 단계의 두 번째 호출을 거부하고 다른 단계에서는 한 번 사용할 수 있다.
- 발사 취소, 첫 충돌 안내, 선택 도전·기록 보호, 실패 인과 강화, 과거 공 회수, 공 꾸미기 렌더 연결을 위젯 테스트로 확인한다.
- 보상·저장·중복 입력 집중 회귀 128건: 통과.
- 전체 Flutter 회귀 768건: 통과.
- `flutter analyze`: 이슈 0건.
- Web Release 빌드: 통과.
- 생성 카탈로그 `--check`, 단계 JSON 구문, `git diff --check`: 통과.
- 현재 시도와 최고 기록을 분리하고, 기록 보호 복원과 되감기 시도 범위를 검증했다.
- 발사 취소·과거 공 회수·되감기·재시작·다음 단계·기록 재도전은 저장 중 중복 입력과 교차 실행을 막는다.
- `StagePatternSession`의 공개 상태 작업도 인스턴스별 비동기 큐에서 직렬화하므로 UI를 우회한 동시 보상 사용이 앞선 저장을 덮어쓰지 않는다.
- 제거된 보상 ID가 저장돼 있으면 같은 seed로 현재 카탈로그의 정상 후보 세 개를 복구하고 선택 대기로 돌아간다.
- 독립 Luna 재감사는 상태 유실·단계 사용 키·결과 문구·구형 후보 복구 보정을 확인하고 미해결 P0·P1·P2 없음으로 PASS했다.
- 공 꾸미기 토글 전후 동일 입력의 경로·사건·단계 판정·공 크기가 같음을 회귀로 고정했다. 꾸미기 집중 Golden·보상 모델·선택 팝업·실제 선택/복원 연결 46건과 `flutter analyze`가 통과했다.

## 잔여 위험

- 현재 보상 수치는 프로토타입 기준이며 실제 사용자에게 각 보상의 선택률과 체감 가치가 균형적인지는 플레이테스트가 필요하다.
- 첫 충돌 대상 안내는 충전 중 현재 힘으로 80ms마다 갱신한다. 마지막 화면 갱신과 손을 떼는 순간 사이의 매우 짧은 입력 차이는 남을 수 있으나 궤적을 숨기는 제품 원칙은 유지한다.
- 데모 리더보드는 서버 순위가 아닌 로컬 예시 기록이다.
