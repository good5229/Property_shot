# PS-STAGE-03 6단계 속도를 되살리는 길 검증

기준일: 2026-08-07 KST

## 범위

감속 중인 공이 파워 슬라이더에 진입해 진행 방향을 유지한 채 기준 속력을 회복하는 학습을 네 개의 데이터 패턴으로 검증한다. 판정은 기존 결정론적 `ShotResolver`와 `StagePattern` 원본 JSON을 사용하며, 새 물리 법칙은 추가하지 않았다.

## 학습·패턴 계약

| 패턴 | 권장 경로 | 실제 구성 | 대체 경로 |
|---|---|---|---|
| `stage_speed_01` | 마지막 구간 재가속 | 공·벽·상자·홀·`last_slider` | 슬라이더 없이 벽 우회 |
| `stage_speed_02` | 벽 반사 후 슬라이더 진입 | 공·내부 벽·슬라이더·상자·홀 | 슬라이더 없이 외곽 반사 |
| `stage_speed_03` | 상자를 민 뒤 재가속 | 공·상자·슬라이더·벽·홀 | 상자를 거치지 않는 반사 우회 |
| `stage_speed_04` | 복수 슬라이더 선택 | `left_slider`·`right_slider`·상자·홀 | 중앙 직행 우회 |

모든 패턴은 `none`을 허용 전략으로 선언한다. 6단계는 특정 발판을 수행해야만 클리어되는 구조가 아니며, 파워 슬라이더는 공 또는 허용된 이동 물체의 실제 swept 경로에 들어왔을 때만 작동한다.

## 해법 탐색 결과

각도 2도, 힘 2% 간격으로 힘 12~100%를 조사했다. 성공은 `GamePhase.success`, 슬라이더 성공은 실제 `PowerSliderActivation`, 우회는 해당 이벤트가 없는 성공으로 집계했다.

| 패턴 | 전체 성공 | 슬라이더 성공 | 약한 슬라이더 성공(40% 이하) | 슬라이더 없는 성공 | 대표 입력 | 대표 속도 변화 |
|---|---:|---:|---:|---:|---|---|
| 1 | 1,515 | 1,290 | 283 | 225 | 58도 / 32% | 5.617 → 42.000 |
| 2 | 1,653 | 1,040 | 70 | 613 | 66도 / 62% | 5.885 → 40.000 |
| 3 | 604 | 396 | 33 | 208 | 210도 / 56% | 3.239 → 44.000 |
| 4 | 1,079 | 752 | 52 | 327 | 40도 / 80% | 3.847 → 46.000 |

대표·약한 발사·우회 fixture는 `test/fixtures/stage_speed_patterns.dart`에 수치로 고정했다.

- 1번 약한 대표: 58도 / 32%, `last_slider`
- 2번 대표: 66도 / 62%, `bank_wall → after_bank_slider`; 약한 대체 216도 / 40%
- 3번 대표: 210도 / 56%, `push_crate` 이동과 이후 `crate_slider` 작동; 약한 슬라이더 경로는 222도 / 28%
- 4번 선택: 오른쪽 40도 / 80%, 왼쪽 약한 경로 222도 / 40%
- 슬라이더 미사용 우회: 52도 / 44%, 90도 / 52%, 50도 / 68%, 68도 / 72%

3번의 현재 물리 이벤트는 상자 이동을 먼저 확정한 뒤 같은 발사의 후속 공 경로에서 슬라이더를 작동시킨다. `push_crate` impact와 `crate_slider` activation의 `pathIndex` 순서를 회귀로 확인하며, 접촉 주체·이벤트 이름을 근거 없이 상자로 바꾸지 않는다.

3번의 대표 경로와 약한 경로는 서로 다른 허용 해법이다. 대표 210도·56%는 `push_crate impact → 상자 이동 → crate_slider activation → 홀`을 증명하고, 222도·28%는 상자를 건드리지 않는 저출력 재가속을 증명한다. 원문의 `상자를 민 뒤 재가속` 패턴과 `약한 발사 후 재가속` 학습 목표를 각각 만족하며, 둘을 하나의 정답 입력으로 강제하지 않는다.

## 합격 조건

- `max(현재 속력, 기준 속력)`만 적용되며 단순 가산하지 않는다.
- 한 접촉 ID는 한 번만 작동하고, 완전히 이탈한 뒤 재진입할 때만 다시 작동한다.
- 모든 기준 속력은 48 이하이며 대표·고속 발사 결과에 `chainSafetyStop`이 없다.
- 고속 발사도 activation 이벤트와 유한한 경로를 남기며 발판을 건너뛰지 않는다.
- 2번은 내부 벽 impact가 슬라이더 activation보다 앞선다.
- 3번은 상자 이동이 슬라이더 activation보다 앞선다.
- 4번은 왼쪽·오른쪽 슬라이더를 서로 다른 성공 입력으로 선택할 수 있다.
- 네 패턴 모두 슬라이더가 없는 독립 성공 입력을 가진다.
- 네 대표 경로 모두 발판 진입 전 속력이 최초 발사 속력보다 낮고, 발판 작동 후 다시 높아진다.

## 남은 위험

- 실제 모바일에서 40% 이하 힘의 발판 진입 조작감과 슬라이더 시각 피드백은 실기기 수동 QA가 필요하다.
- 3번은 현재 엔진의 이벤트 모델상 상자 이동과 공의 후속 재가속을 한 흐름으로 학습한다. 향후 이동 물체의 독립 속도 객체를 도입하면 접촉 주체별 `resultingVelocity` 계약을 다시 검토해야 한다.
- Web 성능과 iOS·Android 실기기 프레임·햅틱은 이 작업에서 새로 판정하지 않는다.

## 독립 QA 판정

구현에 참여하지 않은 별도 QA 에이전트가 원본 요구사항, JSON·생성본, 실제 사건 로그, fixture, 리플레이, 지도·결과 화면을 재검토했다. 첫 감사에서는 3번의 상자 이동 경로와 약한 경로를 한 입력으로 결합해야 한다고 해석했으나, 원문과 특정 기믹 비강제 원칙을 대조하고 두 독립 해법의 실제 사건을 재확인한 뒤 이 지적을 철회했다. 대표 경로의 감속 전후 속력 직접 검증까지 보강한 최종 판정은 P0·P1·P2 없이 `PASS`다.
