# 최종 품질 실험 요약

작성 기준: 2026-08-03 KST
상태: 중간 결과 기록

## 실험 목적

속성 이전·복사, 결정론 물리, 다중샷 연쇄, 4단계 퍼즐, 한글 모바일 UX, 저장·해금, 비주얼·타격감이 하나의 제품 흐름으로 작동하는지 검증한다. 앱스토어 출품 자체가 아니라 데모의 품질과 확장 가능성을 판단한다.

## 현재 확보한 결과

- 4개 단계와 지도 해금·클리어 팝업 흐름 구현
- 순수 Dart `ShotResolver`와 렌더링 재생 분리
- 벽 불변성·대상별 충돌·홀 우선·이전 공 연쇄 회귀 추가
- 일반 풍선 반사와 뾰족함 풍선 파괴의 분기 확인
- 진행 저장 버전·구버전 키·손상 값 복구 구조 구현
- 로컬 계측 이벤트를 실제 UI·물리 상태 전이에 연결
- 전체 `flutter test` 252개, 다중샷 물리 분석·저장 다중샷 재생 통과
- 4단계 각각 성공 2개·실패 2개씩 총 16개 저장 리플레이 픽스처와 결정론 재생 검증 통과
- 4개 단계 × 5개, 총 20개 다중샷 리플레이와 발별 물리 지문 재생 검증 통과
- 네 단계 모두 최소 1개의 실제 2발 상태 전달 시나리오를 포함하도록 픽스처 격자와 회귀 조건 보강
- 개발 전용 튜토리얼 조건군 3종과 조건별 세션 계측 연결, 선택기 회귀 통과
- 개발 전용 진단 메뉴에서 단계 이동·진행 초기화·전체 해금·복제 코어·속성 강제 장착·물리 이벤트·히트박스·법선·프레임 통계를 조정·관찰할 수 있고, Release 번들 비노출을 확인
- 원본 속성 제거·복원, 공 질량·속도·운동량·샷·충돌 식별자, 리플레이 녹화·재생, 사운드·햅틱 토글까지 Debug 메뉴에 연결하고 한글 표시를 확인
- Web Release 빌드 및 다섯 뷰포트 캡처 확인
- Android 호스트를 추가하고 Debug·Release APK 컴파일 통과를 확인
- Apple Silicon 호환 Android ARM64 API 28 에뮬레이터에서 Release APK 설치·실행과 1단계 물체 팝업·속성 옮기기 흐름을 실제 입력으로 확인
- Android ARM64 에뮬레이터 Release 재생에서 지도 4/4·4단계 진입·뾰족함 이전·충전·자동 발사·문 열림·홀 성공·클리어 팝업까지 확인
- 단계4 실제 Web 조작을 390×844에서 재생해 시작·속성 이전·조준·충전·충돌·결과 8장을 확보했고 콘솔 오류 0건을 확인
- 성공 후 `active_ball` 부재로 발생하던 Web 예외를 수정하고 상태 렌더 회귀를 추가
- 앱 재실행을 가정해 새 저장소 인스턴스에서 클리어·최고 기록·추가 도전·복제 코어 복원을 검증
- 플레이 계측은 최근 2,000개를 250ms 묶음으로 로컬 저장하고 조회·화면 종료 시 flush하도록 보강
- 계측 이벤트에 안정 `stage_id`, `result_code`, `route_tag`와 CSV 열을 추가하고 `898afd2`로 push
- `flutter build ios --no-codesign`에서 Xcode 컴파일 완료, 서명 팀·프로비저닝 부족으로 배포 단계 차단을 확인
- 최신 Web 성능 감사 실행 환경을 Pillow 12.3.0 격리 가상환경으로 복구하고 Long Task 수집을 추가했다. no-cache 번들의 5초 워밍업 발사 평균·p95는 390×844에서 25.681·66.6ms, 768×1024에서 35.953·66.7ms로 60FPS 성능 게이트는 미통과이며, 빈 Chromium 기준은 약 16.7ms였다.

## 잠정 판정

현재는 자동 검증과 Web 수직 슬라이스를 통과한 `실험 진행 중` 상태다. 실기기·외부 플레이테스트·최종 라이선스 증거가 없으므로 최종 `Go`, `Conditional Go`, `No-Go` 판정은 보류한다.
