# 30~60 FPS 충돌 애니메이션 검증

## 원인

- 기존 화면 흔들림은 물리 경로 커서에 `5.6`, `6.4`를 곱한 고주파 위상을 사용했다.
- 애니메이션 커서는 초당 34단위이므로 30 FPS에서는 프레임마다 약 6.35라디안, 60 FPS에서는 약 3.17라디안씩 위상이 바뀌었다. 결과적으로 30 FPS에서는 거의 한 주기, 60 FPS에서는 거의 반 주기를 건너뛰었다.
- Y축이 `cos(0)`에서 시작해 충돌 첫 프레임에 보드 전체가 즉시 이동했다. 실제 처리 지연과 별개로 사용자는 이를 충돌 순간의 끊김으로 보게 된다.
- 렌더 단계도 카메라·충돌 효과·탄성 공 변형을 계산할 때 전체 과거·미래 사건 목록을 매 프레임 반복 탐색했다.

## 수정

- 흔들림을 충돌 시점의 0 오프셋에서 시작하는 6Hz 초 단위 곡선으로 바꾸고, 8 경로 단위 동안 제곱 감쇠한다.
- 이동·충돌·인과 사건을 샷 적용 시 한 번 정렬하고 이진 탐색으로 현재 효과 구간만 조회한다.
- 엔티티 변형은 전체 이동 목록 대신 엔티티별 캐시를 사용한다.
- 연쇄 이동 경로의 총거리는 샷 준비 시 계산한 값을 재사용한다.
- 물리 해석, 충돌체, 경로 결과, 재생 속도는 변경하지 않았다.

## 자동 검증

| 항목 | 결과 |
|---|---|
| 30·45·60 FPS 충돌 첫 프레임 | 오프셋 0, 순간 이동 없음 |
| 30·45·60 FPS 인접 프레임 | 흔들림 변화량 상한 통과, 3프레임 이상 감쇠 표시 |
| 30~60 FPS 불규칙 프레임 | 커서 단조 증가, 프레임당 30 FPS 상한 준수 |
| 물리 사건 | 원래 순서 그대로 정확히 한 번씩 방출 |
| 충돌·회전판·기믹 Golden | 63건 통과 |
| 전체 Flutter 회귀 | 2,018개 테스트 이벤트 성공 |
| 정적 분석 | 문제 0건 |
| 생산 패턴 | 10단계×4패턴 런타임 검증 및 생성본 일치 |
| Web 출시본 | `flutter build web --release --wasm` 성공 |
| 로컬 Wasm 브라우저 | 홈·1단계·속성 이전 진입, 자산 HTTP 200, 콘솔 오류 0건 |

## 범위

- 브라우저 자동 검수는 Wasm 번들의 로딩·화면 진입·콘솔 오류를 확인했다.
- 충돌 시간축과 카메라 연속성은 결정론적 엔진 테스트와 Golden으로 검증했다. 실제 저사양 기기의 GPU·디스플레이 주사율·브라우저 백그라운드 스케줄링까지 동일하다고 단정하지 않는다.
