# 재미·동기·입력 성능 개선 기록

작성 기준: 2026-08-14 KST

## 문제 정의

기존 게임은 40개 패턴과 9종 보상, 쉬움/보통 모드, L1/L2 힌트를 이미 갖추었다. 그러나 성공 전에는 플레이어가 무엇을 알아냈는지 보이지 않고, 힌트 권한이 없는 플레이어는 막힌 즉시 현재 퍼즐의 구체적 도움을 받기 어려웠다. 입력 경로에서는 포인터가 조금만 움직여도 전체 UI 갱신과 전체 `ShotResolver` 미리보기가 반복될 수 있었다.

따라서 이번 개선의 핵심은 콘텐츠 수를 늘리는 것이 아니라 다음 루프를 화면에 드러내는 것이다.

```text
질문을 본다 → 물리로 시험한다 → 기믹 사건을 발견한다 → 실패해도 발견은 남는다 → 다음 한 발을 수정한다
```

## 반영한 변경

### 1. 스테이지별 발견 임무

- 10개 단계에 각각 다른 관찰 질문과 3개의 인과 마일스톤을 제공한다.
- 보드가 작은 휴대폰에서는 `발견 0/3 · 무거움 → 상자 → 홀`처럼 한 줄로 압축한다.
- 넓은 화면은 질문과 개별 발견 칩을 보여 준다.
- 발견 판정은 기존 `ShotResult`, 물리 이벤트, 장착 속성을 읽기만 하며 발사 입력과 판정을 바꾸지 않는다.

### 2. 실패해도 남는 진전

- 실패 결과에 `실패해도 발견은 남아요` 카드를 추가했다.
- 이번 시도에서 달성한 사건과 다음에 시험할 한 가지를 보여 준다.
- 현재 스테이지를 다시 시도해도 현재 플레이 세션의 발견 표시는 유지된다.
- 클리어 결과는 `이번 탐사 기록`으로 발견한 인과를 요약한다.

### 3. 막힌 시점의 즉시 힌트

- 이전에 보상이나 열쇠를 얻지 못한 패턴도 첫 실패 후 `failure_assist` 출처의 L1 접근권을 얻는다.
- 힌트는 자동으로 팝업하거나 각도·파워 수치를 강제하지 않고, 플레이어가 버튼을 열어 선택한다.
- 기존 열쇠는 즉시 도움 접근 경로, 클리어 보상은 다음 퍼즐의 선제 힌트라는 가치를 그대로 유지한다.

### 4. 입력 경로 중복 작업 축소

- 포인터가 움직여도 1도 조준 구간이 바뀌지 않으면 조준 HUD·테레메트리·미리보기를 다시 갱신하지 않는다.
- 쉬움 모드의 첫 도착점과 `첫 충돌 안내` 보상은 동일한 입력이면 하나의 `ShotResult` 판정을 공유한다.
- 실제 발사는 미리보기 캐시를 신뢰하지 않고 새 `resolve()`로 판정해 입력·리플레이 결정론을 보존한다.
- 로컬 테레메트리는 최대 2,000건의 메모리 링을 유지해 장기 세션 메모리 증가를 제한한다.

### 5. 첫 탄성 학습의 성공 영역 확대

- 신규 캠페인 유저가 처음 만나는 `stage_bouncy_01`의 홀 수용 영역과 접근 가드를 조정했다.
- 동일한 4도×10% 입력 격자에서 탄성 성공점은 19/900에서 34/900으로 늘었고, 무속성 우회는 8/900으로 제한된다.
- 대표 탄성 해법 주변의 15개 입력 중 10개가 성공하며, 탄성/무속성 성공 영역 비는 4.25배다.
- 물리 상수와 탄성 반발 규칙은 바꾸지 않았다. 기존 대표 다중 벽 반사, 대체 해법, 40패턴 기믹 우위와 데모 입력은 그대로 재생된다.

### 6. 도움 설정의 목적별 재구성

- 기존 개별 설정을 `조준 도움`, `경로 기억`, `인과 이해`, `화면과 소리`로 묶어 플레이어가 원하는 도움을 빠르게 찾게 했다.
- `직전 조준 비교`를 독립 설정으로 추가해, 실패 후 회색 비교선이 불필요한 플레이어는 끄도록 했다.
- 이 설정들은 정보 표시만 바꾸며 발사 입력, 물리 판정, 보통 모드 기록과 리플레이는 바꾸지 않는다. 보상으로 제공되는 `정밀 충전 조절`도 무료 토글로 중복하지 않았다.
- 설정 스키마를 5로 올리고, 기존 선택은 그대로 보존하며 새 비교선 설정은 기본 활성화로 이전한다.

### 7. 보상을 ‘선택’에서 ‘실제 활용’으로 연결

- 10종 보상을 직접 사용, 조건부 자동, 런 지속, 선택 즉시의 네 발동 방식으로 분류했다.
- 클리어 보상 선택 카드와 홈의 `내 런 보상` 카드가 동일한 사용법을 보여 준다. 예를 들어 발사 취소는 충전 중 버튼, 과거 공 회수는 실패 후 버튼, 기록 보호는 클리어 시 자동 적용으로 안내한다.
- 스테이지 HUD에는 현재 사용 가능한 보상 중 하나만 우선순위로 표시해 퍼즐 시야를 방해하지 않는다.
- `reward_used`는 선택 시점이 아니라 사용 저장이 성공한 뒤에만 기록한다. 보상 ID, 발동 방식, 사용 키, 단계 범위, 선택 기록, 선택 후 몇 단계 뒤 사용했는지를 남겨 ‘선택했지만 쓰지 않는 보상’을 찾을 수 있게 했다.

### 8. 세 번만 이어 가는 탐사 계약

- 홈에서 `발견 탐사`, `정밀 탐사`, `연쇄 탐사` 중 하나를 고르고 현재 열린 캠페인 단계 3개를 짧은 목표로 묶는다.
- 발견 탐사는 물리 발견 2개, 정밀 탐사는 파 이내 클리어, 연쇄 탐사는 속성·기믹 사건 3종 연결을 단계별 목표로 삼는다.
- 목표를 놓쳐도 캠페인 클리어와 다음 단계 진행은 막히지 않는다. 결과 화면의 압박을 늘리는 대신 같은 스테이지를 다른 관점으로 다시 보게 하는 선택 목표다.
- 계약 진행은 전용 SharedPreferences 키에 저장하고 캠페인 RunState, 오늘의 도전, 최고 기록과 분리했다. 앱을 다시 열어도 완료·목표 달성 상태가 복원된다.
- 320×568 선택 화면과 390×844 진행 화면 Golden으로 스크롤, 잠금 설명, 목표 진행도를 확인했다.

## 검증 결과

| 게이트 | 결과 |
|---|---|
| `flutter analyze` | 문제 0건 |
| 발견·힌트·RunState·테레메트리·UI 표적 회귀 | 210/210 통과 |
| 10단계 전체 화면·게이지·힌트·특수 기믹 시각 회귀 | 194/194 통과 |
| 40패턴 기믹 우위·리플레이 결정론·캡처 | 12/12 통과 |
| 미리보기 `ShotResult` 공유과 독립 계산 동치 | 단위 회귀 통과 |
| 작은 화면 | 320×568 보드 폭·HUD 비중첩 및 Golden 통과 |

이 숫자는 이번 변경의 영향권과 물리 결정론을 검증한 표적 실행 결과다. 최종 전체 실행에서 기능 검증 1,006건은 통과했고, 새 HUD가 반영되지 않은 특수 화면 Golden 71건을 발견했다. 차이가 발견 HUD에만 국한됨을 시각 확인한 뒤 71건을 갱신하고 비갱신 모드로 71/71 재통과했다. 전체 직렬 실행은 중복하지 않았다. 실제 재미·이탈률·실기기 프레임 지표를 통과했다는 의미는 아니다.

## 남은 검증과 후속 순서

1. 초행 사용자 12~20명의 A/B 플레이테스트로 첫 발사·발견·재시도·이탈을 측정한다.
2. 3스테이지 탐사 유형별 선택률·완료율·다른 유형 재도전률을 측정하고, 그 결과를 인과 도감 확장 여부의 근거로 사용한다.
3. 실제 Chrome 프로파일과 Android/iOS 실기기에서 조준 중 프레임, 입력 p95, 메모리를 다시 측정한다.
4. 사용자 지표가 개선된 뒤에만 3스테이지 탐사·속성 도감·결과 화면 재구성을 확장한다.
