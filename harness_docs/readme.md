# 모바일 캐주얼 게임 `Property Shot` 프로토타입 개발 프롬프트

## 1. 역할

당신은 모바일 캐주얼 게임의 시스템 설계와 Flutter/Flame 구현을 담당하는 시니어 게임 클라이언트 개발자다.

이 작업의 목표는 상용 서비스 전체를 만드는 것이 아니라, 게임의 핵심 재미를 검증할 수 있는 **플레이 가능한 수직적 프로토타입**을 만드는 것이다.

불필요한 기능을 확장하지 말고, 아래에 정의된 코어 메커니즘이 실제 플레이에서 이해 가능하고 재미있는지를 검증하는 데 집중하라.

---

## 2. 프로젝트 개요

### 프로젝트 코드명

`Property Shot`

### 장르

속성 조합형 물리 퍼즐·스코어 어택 모바일 게임

### 한 문장 설명

주변 물체에서 물리적 속성을 훔쳐 공에 장착하고, 골프처럼 충분히 조준한 뒤 한 번의 샷으로 연쇄 반응을 설계하는 모바일 캐주얼 게임이다.

### 핵심 차별점

일반적인 골프 게임은 공의 방향과 세기를 조절한다.

이 게임에서는 플레이어가 환경의 물체에서 `무거움`, `탄성`, `접착` 등의 속성을 훔쳐 공에 장착할 수 있다.

공이 속성을 얻으면 원래 물체는 해당 속성을 잃으며, 그 결과 공뿐 아니라 맵 전체의 상태가 함께 변한다.

즉, 플레이어는 단순히 공을 발사하는 것이 아니라 다음 두 가지를 동시에 계산해야 한다.

1. 속성을 얻은 공이 어떻게 움직이는가
2. 속성을 빼앗긴 원래 물체가 어떻게 변하는가

## 3. 대상 사용자와 플레이 환경

### 대상 사용자

- 20~50대의 일반 모바일 게임 사용자
- 특정 장르에 숙련된 매니아가 아닌 대중적인 사용자
- 지하철, 버스, 대기시간 등에 짧게 플레이하는 사용자

### 목표 플레이 시간

- 정상적으로 게임오버되지 않을 경우 한 판 약 8~12분
- 초기 프로토타입에서는 3개의 짧은 테스트 맵으로 핵심 재미를 검증
- 장기적인 콘텐츠와 메타 시스템은 현재 구현 대상에서 제외

### 입력 환경

- 스마트폰 세로 화면
- 한 손 또는 한 손가락으로 조작 가능
- 빠른 연타나 정밀한 실시간 컨트롤을 요구하지 않음
- 플레이어에게 충분한 관찰 및 판단 시간을 제공
- 지하철의 흔들림으로 인한 오입력을 고려

### 테스트 대상 기기

- iPhone 12
- iPad Pro

iPhone과 iPad에서 같은 게임 규칙이 유지되도록 논리 좌표계와 화면 렌더링을 분리하라.

## 5. 핵심 게임 원칙

### 5.1 낮은 입력 빈도, 높은 선택 영향

플레이어는 연속적으로 많은 명령을 입력하지 않는다.

한 번의 속성 선택과 한 번의 샷이 맵 전체에 큰 영향을 주어야 한다.

### 5.2 계획과 실행의 분리

한 턴은 다음 구조를 따른다.

1. 맵을 관찰한다.
2. 속성을 훔칠 물체를 선택한다.
3. 선택한 속성을 공에 장착한다.
4. 공의 방향과 세기를 조절한다.
5. 예상 경로를 표시하지 않은 채 충돌 결과를 생각한다.
6. 필요하면 스킬을 사용한다.
7. 공을 길게 눌러 힘을 모은 뒤 손을 뗀다.
8. 공과 물체의 움직임을 관찰한다.
9. 변화한 맵에서 다음 행동을 계획한다.

단순히 드래그한 뒤 손을 놓으면 조준만 고정되어야 한다. 힘을 모으기 위한 길게 누르기를 끝내고 손을 놓을 때만 자동 발사한다.

조준은 드래그로 변경하고, 공을 길게 눌러 힘을 조절한 뒤 손을 놓으면 실제 샷이 자동 실행된다. 별도의 발사 버튼은 두지 않는다.

### 5.3 플레이어의 핵심 만족감

플레이어가 가장 크게 느껴야 하는 감정은 다음과 같다.

> 여러 물체의 성질과 이동을 계산해 한 번의 샷으로 자신이 의도한 연쇄 반응을 성공시키는 만족감

### 5.4 실패의 납득 가능성

올바른 판단을 했는데 무작위 물리 오차로 실패하는 상황을 최소화하라.

플레이어가 실패했을 때 다음 플레이에서 무엇을 바꾸어야 하는지 이해할 수 있어야 한다.

## 6. 혼합형 물리 시스템

이 게임은 순수 물리 시뮬레이션이 아니라 **결정론적 판정과 물리적 연출을 결합한 혼합형 시스템**으로 구현한다.

### 6.1 결정론적으로 처리할 요소

다음 요소는 동일한 초기 상태와 동일한 입력에서 항상 같은 결과를 내야 한다.

- 어떤 물체와 충돌하는가
- 속성 효과가 발동하는가
- 스위치가 눌리는가
- 문이 열리는가
- 홀 진입에 성공하는가
- 장애물을 밀 수 있는가
- 속성을 빼앗긴 원본 물체가 어떻게 변하는가
- 점수 및 성공 판정
- 게임 상태 전이

### 6.2 물리적으로 연출할 요소

다음 요소는 시각적인 손맛을 위해 물리적으로 표현할 수 있다.

- 공의 회전
- 공이 굴러가고 튀는 애니메이션
- 물체의 흔들림
- 충돌 시 압축·변형
- 파편과 장식물의 이동
- 충돌 후 정지 위치의 미세한 시각적 차이
- 카메라 흔들림
- 진동 및 효과음

단, 시각적 연출의 미세한 차이가 핵심 성공과 실패 판정을 변경해서는 안 된다.

### 6.3 구현 권장 방식

게임 로직과 화면 애니메이션을 분리하라.

권장 처리 순서는 다음과 같다.

```text
현재 GameState
→ 플레이어 입력 확정
→ 논리적 결과 상태 계산
→ 충돌 및 속성 효과 판정
→ 다음 GameState 확정
→ 확정된 상태 전이를 애니메이션으로 재생
```

물리 엔진이 게임 규칙을 직접 지배하게 하지 말고, 논리 엔진이 정한 결과를 물리적으로 재생하는 구조를 우선 고려하라.

## 7. 기본 속성 시스템

최초 프로토타입에서는 다음 속성만 구현한다.

### 7.1 무거움 `Heavy`

공에 장착했을 때:

- 가벼운 장애물을 밀 수 있다.
- 무게 조건이 있는 스위치를 누를 수 있다.
- 충돌 시 더 큰 힘을 전달한다.

원래 물체가 속성을 잃었을 때:

- 다른 물체에 쉽게 밀린다.
- 무게 스위치를 누르지 못한다.
- 기존에 고정되어 있던 위치가 불안정해질 수 있다.

### 7.2 탄성 `Bouncy`

공에 장착했을 때:

- 벽이나 장애물에 충돌하면 지정된 방향으로 반사된다.
- 첫 번째 반사 방향까지 예상 경로를 표시할 수 있다.

원래 물체가 속성을 잃었을 때:

- 충격을 흡수하는 일반 물체로 변한다.
- 공을 튕겨내지 않는다.

### 7.3 접착 `Sticky`

공에 장착했을 때:

- 처음 충돌한 유효 표면에 붙는다.
- 벽이나 움직이는 물체에 부착할 수 있다.

원래 물체가 속성을 잃었을 때:

- 표면이 미끄럽거나 일반적인 충돌 표면으로 바뀐다.
- 기존에 붙어 있던 물체가 있다면 분리 여부를 명확한 규칙으로 처리한다.

### 7.4 속성 이전의 기본 규칙

- 한 턴에 기본적으로 속성 하나만 이전할 수 있다.
- 속성을 공에 장착하면 원래 물체에서는 해당 속성이 제거된다.
- 동일 속성을 중복 장착할 수 있는지는 최초 프로토타입에서는 허용하지 않는다.
- 공이 이미 속성을 가지고 있다면 교체하거나 기존 속성을 반납하는 명확한 규칙을 적용한다.
- 속성 이전은 화면에서 명확한 아이콘 이동 애니메이션으로 표현한다.
- 속성을 잃은 물체의 외형도 즉시 변해야 한다.

## 8. 플레이어 조작

### 8.1 속성 선택

- 속성을 가진 물체를 탭한다.
- 해당 물체의 속성 아이콘을 표시한다.
- 속성 아이콘을 공으로 드래그하거나, 속성을 탭한 뒤 공을 탭해 이전한다.
- 모바일 오입력을 줄이기 위해 선택 상태를 시각적으로 명확하게 표시한다.

### 8.2 조준

- 공 주변에서 손가락 또는 마우스를 움직이는 방향으로 발사 방향을 정한다.
- 골프 또는 슬링샷 게임처럼 직관적으로 조작되도록 한다.
- 방향을 정한 뒤 공을 길게 눌러 힘을 모은다.
- 조준 중에는 빨간 화살표와 공 주변의 힘 게이지로 현재 방향과 세기를 표시한다.
- 공을 천천히 점멸시켜 다음 입력 대상임을 안내한다.

### 8.3 발사

- 공을 누른 상태에서 손을 떼면 현재까지 모인 힘으로 자동 발사한다.
- 발사 전에는 속성, 방향, 세기를 다시 변경할 수 있다.
- 발사 애니메이션과 연쇄 충돌이 끝날 때까지 중복 입력·되감기·단계 이동을 막는다.

### 8.4 예상 경로

발사 전에는 충돌 여부나 최종 목적지까지의 궤적을 보여주지 않는다.
플레이어가 선택한 방향과 힘만으로 결과를 예측하고, 실제 충돌 시점부터 반사·운동량 전달·연쇄 반응을 확인하게 한다.

## 9. 실패한 공의 누적

실패한 샷의 공을 즉시 제거하지 않는다.

맵에 남은 공은 다음 샷에서 다음 역할을 할 수 있다.

- 장애물
- 반사 지점
- 다른 공을 밀어내는 물체
- 스위치를 누르는 무게추
- 새로운 속성 이전 대상
- 다음 연쇄 반응의 재료

실패는 단순한 감점이 아니라 다음 전략의 일부가 되어야 한다.

다만 공이 지나치게 누적되어 게임이 불가능해지는 상황을 막기 위해 테스트 맵에서는 공 개수 제한이나 재시작 기능을 제공할 수 있다.

## 10. 초기 프로토타입 콘텐츠

최초 구현 범위는 다음으로 제한한다.

### 필수 오브젝트

- 공
- 홀 또는 목표 지점
- 일반 벽
- 움직일 수 있는 상자
- 탄성 젤리 또는 범퍼
- 접착 표면
- 무게 스위치
- 스위치로 열리는 문

### 필수 속성

- 무거움
- 탄성
- 접착

### 필수 기능

- 속성 선택 및 이전
- 원본 물체의 속성 제거
- 방향과 세기 조절
- 공을 길게 눌러 힘을 조절한 뒤 손을 떼면 자동 발사
- 조준 중에는 방향 화살표와 힘 게이지만 표시하고 최종 예상 경로는 표시하지 않음
- 결정론적 충돌 및 성공 판정
- 물리적인 이동 애니메이션
- 실패한 공의 맵 잔류
- 맵 초기화
- 일시정지
- 성공 및 실패 메시지
- 간단한 점수 또는 샷 수 표시

### 테스트 맵

최소 3개를 구현한다.

#### 맵 1: 무거움 학습

- 공과 홀 사이에 가벼운 상자가 있다.
- 일반 공은 상자를 충분히 밀지 못한다.
- 무거운 물체에서 `무거움`을 가져오면 상자를 밀고 목표에 도달할 수 있다.
- 속성을 빼앗긴 원래 물체가 가벼워졌음을 화면에서 확인할 수 있어야 한다.

#### 맵 2: 탄성 학습

- 홀로 직접 이동할 수 없는 벽 구조를 사용한다.
- 젤리 또는 범퍼에서 `탄성`을 가져온 뒤 벽에 반사시켜 목표에 도달한다.
- 첫 번째 반사 방향까지만 예상 경로로 제공한다.

#### 맵 3: 복합 연쇄 반응

- 무게 스위치와 문을 배치한다.
- 공에 속성을 장착해 스위치를 누르고 문을 열어야 한다.
- 첫 샷이 실패하더라도 맵에 남은 공을 다음 샷의 도구로 사용할 수 있게 한다.
- 하나 이상의 해결 방법이 존재하면 좋다.

## 11. 스킬 시스템

프로토타입에서는 핵심 메커니즘 검증이 우선이므로 스킬을 과도하게 추가하지 않는다.

다음 중 최대 2개만 구현한다.

### 되감기

- 직전 발사 전의 GameState로 복원한다.
- 물리 시뮬레이션을 역재생하지 말고 저장된 상태를 복원한다.
- 테스트 편의를 위해 맵당 1회 또는 무제한 디버그 모드로 제공할 수 있다.

### 속성 복사

- 원래 물체의 속성을 제거하지 않고 공에 동일한 속성을 복사한다.
- 일반적인 속성 이전과 분명히 구분되는 시각 효과를 사용한다.
- 제한 횟수를 표시한다.

초기 코어 플레이가 충분히 재미있지 않다면 스킬로 문제를 가리지 말고 핵심 규칙부터 수정하라.

- 점수 또는 목표 상태

### 중앙

- 게임 필드
- 공과 오브젝트

- 조준 방향 표시와 공 주변 힘 게이지
- 스위치와 문 상태

### 하단

- 선택 가능한 스킬
- 속성 옮기기 또는 복사 명령
- 힘 조준이 끝나면 자동 발사되므로 별도 발사 버튼은 두지 않는다.

주요 버튼이 화면 끝으로 지나치게 멀어지지 않도록 중앙 정렬된 UI 영역을 사용한다.

## 17. 테스트 요구사항

최소한 다음 테스트를 작성하라.

### 단위 테스트

1. 동일한 초기 상태와 동일한 발사 입력은 동일한 최종 상태를 생성한다.
2. 무거운 공은 지정된 상자를 밀 수 있다.
3. 일반 공은 무게 조건이 있는 스위치를 누르지 못한다.
4. 무거운 공은 무게 스위치를 누른다.
5. 탄성 공은 지정된 충돌 규칙에 따라 반사된다.
6. 접착 공은 첫 유효 표면에 부착된다.
7. 속성을 공에 이전하면 원래 물체에서 해당 속성이 제거된다.
8. 되감기 시 발사 전 상태와 동일한 상태가 복원된다.
9. 문이 열린 상태에서만 공이 통과할 수 있다.
10. 홀 진입 판정이 애니메이션 프레임 속도에 영향을 받지 않는다.

### 위젯 또는 통합 테스트

1. 속성 아이콘을 선택하고 공에 이전할 수 있다.
2. 방향 조준만으로는 발사되지 않고, 공을 길게 눌러 힘 조준을 끝내면 자동 발사된다.
3. 발사 중에는 중복 발사가 차단된다.
4. 화면 크기가 달라도 핵심 UI가 잘리지 않는다.
5. iPhone 세로 화면과 iPad 화면에서 플레이 영역이 정상 표시된다.

### 수동 플레이테스트 체크리스트

- 별도 설명 없이 속성을 공으로 옮길 수 있는가
- 조준 방식이 10초 이내에 이해되는가
- 속성을 빼앗긴 원래 물체의 변화가 인식되는가
- 실패 원인을 플레이어가 설명할 수 있는가
- 성공했을 때 연쇄 반응이 만족스럽게 보이는가
- 실패한 공을 다음 샷에서 전략적으로 사용할 수 있는가
- 같은 맵을 두 번 이상 다시 시도할 이유가 있는가
