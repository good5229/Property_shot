## 활성화 규칙

에이전트는 아래 여섯 항목을 확인하고 서명한 뒤에만 제안·구현을 시작한다.

1. 자신의 역할 매뉴얼을 읽었다.
2. `README.md`, `harness_docs/readme.md`, 최신 공통 컨텍스트와 관련 설계·QA 문서를 읽었다.
3. 역할 참고자료 색인에서 필요한 외부 자료를 확인했다.
4. 이번 작업의 포함 범위를 한 문장으로 썼다.
5. 이번 작업에서 하지 않을 일을 한 문장으로 썼다.
6. 어떤 동료가 무엇을 검토할지 적었다.

## 활성화 판정

- `교차 검토 대기`: 문서 읽기와 참고자료 확인은 했지만 동료 검토 결과를 반영하지 않은 상태.
- `보완 후 검토`: 독립 검토에서 P1 보완 항목이 발견되어 문서 수정 후 다시 검토해야 하는 상태.
- `활성화`: 역할 범위·비범위·검토자·외부 근거·검증 명령이 확인되고 P0/P1 미해결이 없는 상태.
- `범위 활성화`: 이번 목표의 저장소 구현 범위는 검증됐지만 실제 기기·법무·사용자 검증 같은 외부 조건이 남아 전체 활성화로 승격하지 않은 상태.
- 실제 구현은 모든 구현 역할이 `활성화`가 된 뒤에만 시작한다.

## 이번 활성화 상태

초기 표의 `교차 검토 대기`와 `보완 후 검토`는 구현 전 상태를 기록한 것이다. 2026-08-03 교차 검토와 구현 후 재판정에서 이번 목표에 필요한 게임 디렉터, 아트·기술 아트, UX 라이터·디자이너, 레벨·시스템, 물리, VFX, QA, 접근성, 성능, 제품 평가, 라이선스, Git·릴리스 역할을 `범위 활성화`로 재판정했다. 근거는 [역할 교차 검토 기록](manual_cross_review_2026-08-03.md), [스테이지4 인과 검증](../qa/stage4_causality_validation.md), 18종 매뉴얼의 공식 참고자료 색인, 자동 회귀·Golden·Web 빌드 결과다.

이번 범위에서 확인한 P0는 없다. 다만 다음은 외부 검증이므로 전체 제품 활성화로 과장하지 않는다.

- 실제 iOS·Android 기기에서 접근성 트리와 동작 저감 상태 확인
- 상용 자산의 최종 법무·크레딧 검토
- 실제 사용자 플레이테스트와 장시간 고속 연쇄 스트레스 테스트
