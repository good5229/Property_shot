## 구현 전 차단 P0

### 물리·연출 이벤트 계약

현재 물리 이벤트와 `ShotAnimationMove`·문자열 이벤트가 서로 다른 구조로 존재할 수 있으므로, 구현 단계에서 다음 단일 추적값을 도입해야 한다.

- `eventId`
- `parentEventId`
- 충돌 시각 또는 고정 시간 오프셋
- 경로 인덱스
- 접촉 법선
- 충격량·결과 속도
- 원인 엔티티·대상 엔티티

VFX·오디오·분석은 이 확정 이벤트를 읽고, 연출은 판정을 변경하지 않아야 한다.

### 연쇄 안전 종료

`chain_safety_stop`은 문자열 로그가 아니라 중단 객체 ID·반복 수·잔여 거리·잔여 속도·중단 원인을 포함한 구조화 진단이어야 한다. 안전 종료가 발생한 샷은 정상 클리어로 조용히 인정하지 않으며 QA에 노출한다.

## 구현 단계 P1 백로그

- 재질 쌍별 마찰·반발·정지 임계값을 정의하고 사선 충돌을 검증한다.
- 동일 입력의 이벤트 ID·순서·최종 상태를 결정론 Golden으로 고정한다.
- 풍선 일반 반사, 팝, 뾰족함 이전·소모·되감기·초기화를 위치·법선·연쇄 증거와 함께 검증한다.
- QA 매뉴얼의 기준 테스트 수는 실행 시점의 `flutter test --reporter compact` 출력으로 갱신하고, 역사적 수치와 현재 수치를 분리한다.
- 접근성 검증에 Flutter semantics, 대비, 터치 크기, reduced motion, 오디오 없는 플레이를 실제 명령·임계값과 함께 추가한다.
- 성능 검증에 충돌 수·연쇄 깊이·동시 이펙트·초기 로딩·메모리·실기기 조건을 추가한다.

## 활성화 판정

문서 층은 P1 보완을 반영했지만 구현 에이전트는 위 P0가 해결될 때까지 `활성화`로 올리지 않는다. 다음 단계는 물리 이벤트 계약과 연쇄 안전 진단을 먼저 구현하고, 그 뒤 역할별 재검토를 수행한다.

2026-08-03 기준 `PhysicsEvent`·`ChainSafetyDiagnostic`을 구현했다. 전체 Flutter 회귀 174개, `flutter analyze`, Web release가 통과했으며 기존 콜백과 새 스트림의 중복 없는 재생을 확인했다.

- 물리·연출 이벤트 구조화 P0: 구현 완료, 실기기·스트레스 연쇄 검증은 잔여 위험.
- `chain_safety_stop` 구조화 P0: 구현 완료, 정상 클리어 은닉 여부를 고의 스트레스 케이스로 추가 검증해야 함.
- 재질 쌍별 마찰·반발, 실제 post-solve 속도 직접 연결: 다음 P1.
- 구현 에이전트 활성화: 물리 역할은 조건부 재검토 대기, 전체 역할은 다음 Phase 승인 후 활성화.

## 최신 구현 후 재검토

174개는 물리 이벤트 스트림 직후의 역사적 기준이다. 풍선·스테이지4·한글 UI·Golden 보강 이후 최신 검증은 비다중샷 212개와 다중샷 단독 1개로 분리 실행해 모두 통과했다. `flutter analyze`와 `flutter build web --release`도 통과했다.

- 풍선은 일반 공 충돌에서 움직이지 않고 탄성 반사만 수행하며, 고파워일수록 충돌 직전 상대 법선 속도와 반사 충격이 커진다.
- 뾰족한 공의 풍선 팝은 스위치 노출만 만들고 문을 직접 열지 않는다. 스위치 실제 충돌 뒤 연결 문이 열리며, 뾰족함 없는 우회 성공도 자동 검증한다.
- 기본 플레이 Golden 20개와 스테이지4 상태 Golden 25개를 390×844, 393×852, 430×932, 768×1024, 1024×1366에서 고정했다.
- 현재 남은 검증은 실제 iOS·Android 접근성·동작 저감, 자산 법무·크레딧, 사용자 플레이테스트, 장시간 고속 연쇄 스트레스다. 이 항목들은 저장소 자동 검증 통과로 대체하지 않는다.

## Phase 1·2 구현 후 반영

### UX Writer 독립 감사

- P0 문구와 직접 노출 영어 UI는 발견되지 않았다.
- 장착 후 안내가 데스크톱 상태에 남는 문제, 짧은 화면 문구 잘림, 물체별 접근성 이름 중복, `점착`·`접착` 혼용, 스테이지4 풍선→문 인과 문구가 P1로 확인됐다.
- `copy_inventory.md`에 화면·상태·현재 문구·목적·플레이어 질문·문제·제안 문구·글자 수·위치·표시 조건·접근성 대체·채택 여부·관련 테스트 열을 추가했다.

### 스테이지4 구현 검토

- 풍선 팝은 연결 문을 직접 열지 않고 `balloon_switch`를 노출한다.
- 실제 스위치 충돌 뒤 `balloon_gate`만 열린다. 기존 3단계의 무거움 스위치 규칙은 유지한다.
- 통합 테스트가 `balloon_popped → balloon_switch_revealed → balloon_switch_pressed → gate open` 순서를 확인한다.
- 뾰족함을 쓰지 않는 우회 성공도 별도 테스트로 확인한다.
- 풍선 팝 전에는 스위치가 비활성·비표시이고, 팝 후에는 물리적으로 활성화된다.

### 퍼즐·레벨 최종 검토

- P0는 없다.
- 풍선→스위치→문은 화면에서 이해되는 추천 경로로 유지하되 클리어 필수 조건으로 만들지 않는다.
- 일반 공 우회와 뾰족함 이전 경로를 복제 코어 없이 각각 검증한다.
- 다음 난이도 감사에서 뾰족함 경로는 연결 성공영역 100셀·연속 각도 24도·힘 폭 24% 이상, 비뾰족함 대체 경로는 40셀·12도·16% 이상을 기준으로 측정한다.
- 뾰족함 고유 성공영역이 전체 성공영역의 65%를 넘으면 특정 속성 우월성으로 보고 레벨을 재설계한다.
