# 속성 한방 다음 작업 프롬프트·결과 정의

## 문서 목적

이 문서는 현재 `Property Shot / 속성 한방`의 작업 상태를 다음 Subagent 또는 다음 개발 반복에 전달하기 위한 재사용 가능한 프롬프트다. 구현 의도와 검증 결과를 섞지 않고, 현재 확인된 사실·남은 위험·완료 기준·산출물 형식을 함께 정의한다.

## 현재 제품 정의

- Flutter·Flame 기반 세로형 모바일 물리 퍼즐 데모다.
- 핵심 약속은 주변 물체의 `무거움`, `탄성`, `점착`을 공에 담아 한 번의 샷으로 연쇄 반응을 완성하는 것이다.
- 게임 판정은 순수 Dart 결정론적 시뮬레이션이 담당하고 Flame은 확정 상태와 실제 충돌 이벤트를 재생한다.
- 화면은 단일 탑뷰다. 쿼터뷰, 입체 회전, 사용자 카메라 회전은 추가하지 않는다.
- 시작 화면 → 섬 지도 → 플레이 → 결과 팝업 흐름이 연결되어 있다.
- 첫 품질 게이트는 현재 3개 튜토리얼 스테이지다. 품질 검증 전에는 9개 전체 확장을 우선하지 않는다.
- 실제 온라인 랭킹, 로그인, 광고, 결제, 서버 계정은 범위에 포함하지 않는다.
- 실제 App Store 출품 자체는 이번 목표가 아니지만 iOS 런타임 품질과 빌드 원인은 정직하게 기록한다.

## 이번 반복에서 실제로 변경된 사항

### 1. 조준 가이드 리디자인

- 대상 파일: `lib/game/property_shot_game.dart`
- 기존 긴 단색 빨간 화살표와 큰 화살촉을 제거했다.
- 공 뒤에 나무색 큐와 손잡이 표시를 그려 당구·큐 타격의 장력을 전달한다.
- 공과 큐 사이의 탄성 줄을 유지해 드래그 방향을 설명한다.
- 공 앞에는 짧은 점형 마커와 작은 마름모 방향 표식만 표시한다.
- 힘이 커질수록 큐 길이와 점형 가이드 길이가 커진다.
- 원형 힘 게이지는 유지한다.
- 최종 목적지, 전체 반사 궤적, 정답 경로는 표시하지 않는다.
- 물리 입력·판정·충돌 이벤트 순서는 변경하지 않았다.

### 2. 플레이 Golden 갱신

- 대상 파일: `test/goldens/game_screen_stage{1,2,3}_{390x844,768x1024}.png`
- 새 조준 가이드가 3개 스테이지와 2개 세로 해상도에서 픽셀 기준으로 반영되었다.
- `flutter test test/game_screen_golden_test.dart --update-goldens` 통과 후 기준 이미지를 확인했다.

### 3. 브라우저 캡처 범위 확장

- 대상 파일: `scripts/capture_web_screenshots.py`
- 캡처 대상 해상도를 `390×844`, `393×852`, `430×932`, `768×1024`, `1024×1366`으로 확장했다.
- 홈·섬 지도·플레이 상태를 각 해상도별로 생성한다.
- 390px·768px·1024px의 실제 버튼 좌표를 명시하고, 중간 해상도는 검증된 좌표를 보간한다.
- 1024×1366에서 시작 버튼과 지도 버튼이 혼동되던 좌표를 실제 버튼 중심으로 보정했다.
- 최신 캡처는 모두 Chromium 콘솔 오류 0건으로 생성되었다.

## 현재 검증 기준

- `dart format --output=none --set-exit-if-changed .`: 39개 파일, 변경 없음
- `flutter analyze`: 통과, 이슈 없음
- `flutter test`: 159개 통과
- `flutter build web --release`: 통과
- Web 데모 루트 HTTP: 200
- Web `main.dart.js`: 200
- 현재 데모 서버: `http://127.0.0.1:8080`, 최신 PID는 실행 시점 기록을 다시 확인한다.
- 목표 해상도 캡처: 5개 해상도 × 홈·지도·플레이, 콘솔 오류 0건

위 수치는 자동·Web 검증 결과다. 실제 iPhone/iPad 프레임, 메모리, 터치 지연, 햅틱, 사운드, 사용자 이해도 결과로 해석하지 않는다.

## 현재 확인된 P1 위험

### 물리

- `ShotResolver`에 재질별 마찰 계수가 충분히 분리되어 있지 않다. 접선 속도 보존과 사선 충돌을 재검토해야 한다.
- 연쇄 계산의 반복 상한이 긴 연쇄에서 후속 충돌을 누락할 가능성이 있다. 잔여 거리·잔여 속도 기반 종료 또는 명시적인 중단 이벤트가 필요하다.
- 첫 Flame 프레임 지연 시 타임라인 Timer 보조가 충돌 이벤트를 한 번에 방출할 수 있다. 실제 렌더 프레임 지연의 체감 순서를 별도 검증해야 한다.

### 레벨·분석

- 파 산출에 전략별 중복 성공 수가 섞일 수 있다. 전략별 성공률과 허용 전략의 고유 성공률을 분리하고 파 기준을 명시해야 한다.
- 3단계의 무속성·점착 대체 풀이가 기본 저해상도 분석보다 고해상도·다중 샷 분석에 의존한다. 단일 샷 대체 풀이와 다중 샷 대체 풀이를 별도 표로 기록해야 한다.
- 1~3단계 모두에서 허용 전략 밖 우연 풀이와 성공 영역 폭을 고해상도로 확인해야 한다.

### 아트·온보딩

- 래스터 돌·상자·젤리와 Canvas 벽·문·스위치·점착판 사이의 질감과 광원 밀도가 완전히 통일되지는 않았다.
- 홈 화면만으로 `물체 선택 → 속성 이전 → 공 충전·발사`의 세 단계가 충분히 즉시 전달되는지는 미검증이다.
- 결과 화면의 대표 캡처와 최신 추가 도전·최고 기록 상태가 항상 같은 최신 빌드 증거로 묶였는지 확인해야 한다.

### iOS·사용자

- iOS Xcode 컴파일은 가능하지만 Development Team·Provisioning Profile이 없어 서명·설치가 완료되지 않았다.
- iOS Simulator Runtime 부재로 시뮬레이터 실행 검증이 제한되어 있다.
- 실제 iPhone/iPad의 GPU·메모리·프레임·터치·햅틱·사운드는 확인하지 않았다.
- 실제 사용자 플레이테스트 없이 첫 30초·5분 이해도나 재도전 욕구를 주장하지 않는다.

## 다음 작업 지시문

아래 내용을 다음 Subagent 또는 다음 작업 세션의 입력으로 사용할 수 있다.

```text
당신은 Property Shot / 속성 한방의 수석 물리 퍼즐·모바일 QA 엔지니어다.

목표:
현재 3개 튜토리얼의 조작 공정성, 물리 일관성, 대체 풀이 분석 신뢰도를 상용 수직 슬라이스 수준으로 끌어올려라. 화면·속성·복제 코어·단일 탑뷰·한글 UI 원칙은 보존한다.

현재 제품 사실:
- Flutter·Flame, 순수 Dart 결정론 물리, 단일 탑뷰, 세로 모바일 레이아웃.
- 첫 3개 스테이지는 무거움·탄성·장치 연쇄를 가르친다.
- 첫 챕터는 복사 없이 클리어 가능해야 하며 복제 코어는 선택형 보상이다.
- 이미 159개 Flutter 테스트와 6개 플레이 Golden이 있다.
- 최신 조준 표시에는 큐 장력과 짧은 점형 방향 마커가 사용된다.

반드시 조사할 파일:
- lib/game/simulation/shot_resolver.dart
- lib/game/domain/entity_state.dart
- lib/game/analysis/difficulty_analyzer.dart
- lib/game/analysis/multi_shot_analyzer.dart
- lib/game/levels/levels.dart
- test/puzzle_solution_audit_test.dart
- test/difficulty_analyzer_test.dart

구현 요구:
1. 재질별 마찰 또는 접선 속도 규칙을 정의하고 공·벽·상자·돌·젤리·점착판·다른 공의 사선 충돌 회귀를 추가한다.
2. 연쇄 반복 상한을 잔여 속도·잔여 거리와 함께 검토한다. 안전한 중단이 필요하면 조용히 잘라내지 말고 QA 이벤트와 테스트로 드러낸다.
3. 첫 프레임 지연·30/60/120Hz에서 충돌 이벤트가 한 번에 생략되지 않는지 검증한다. 애니메이션은 물리 결과를 바꾸면 안 된다.
4. 파 산출을 전략별 성공률과 고유 성공률로 분리한다. 파 계산에 어떤 분모를 쓰는지 문서에 명시한다.
5. 1~3단계의 단일 샷·다중 샷 대체 풀이, 성공 셀, 연속 각도·힘 폭, 우연 풀이 후보를 별도 보고한다. 특정 기믹을 필수 조건으로 만들지 않는다.
6. 변경 전후 화면에서 조준·충돌·결과 상태를 확인하고, 기존 한글 UI와 단일 탑뷰를 유지한다.

- 전체 flutter test, flutter analyze, dart format.
- flutter build web --release.
- 가능하면 flutter build ios --no-codesign; 실패하면 단계·명령·환경 원인을 정확히 기록한다.
- 390×844·393×852·430×932·768×1024·1024×1366의 홈·지도·플레이 캡처와 콘솔 오류 수.
- 난이도 리포트와 파 산출 전후 비교.
- Subagent 독립 진단·교차 반론·사후 평가.
- 작업 단위별 commit과 push, 최신 Web 서버 교체 및 루트·번들 HTTP 200.

비협상 규칙:
- UI의 사용자 노출 텍스트는 한글이다.
- 탑뷰만 사용하고 회전·쿼터뷰를 추가하지 않는다.
- 최종 정답 궤적을 보여주지 않는다.
- 벽은 움직이지 않는다.
- 홀에 먼저 들어간 공은 뒤 벽과 상호작용하지 않는다.
- 연쇄 이동은 실제 선행 충돌 이후에만 시작한다.
- 이전 공도 물리 객체이며 홀 클리어에 참여한다.

- 기존 사용자 변경을 되돌리지 않는다.
```

## 작업별 결과물 정의

각 다음 반복은 아래 네 묶음을 남긴다.

### 구현 결과

변경 파일, 사용자에게 보이는 변화, 물리·렌더링 분리 여부, 접근성 영향을 기록한다.

### 검증 결과

실행한 명령과 통과·실패·환경상 미실행·실제 기기 필요를 구분한다. 테스트 개수만 쓰지 말고 해당 테스트가 어떤 요구사항을 증명하는지 적는다.

### 시각 결과

변경 전과 변경 후를 같은 해상도·같은 상태로 캡처한다. 홈·지도·플레이·결과를 구분하고, 캡처가 실제 최신 서버에서 생성됐는지 PID·HTTP·콘솔 오류를 기록한다.

### 배포·협업 결과

기능 단위 commit ID, push 브랜치, 서버 교체 PID, Subagent P0/P1, 남은 위험을 기록한다.
