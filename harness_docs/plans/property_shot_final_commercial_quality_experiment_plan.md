# 속성 한방 최종 품질 검증 실험 계획

작성 기준일: 2026-08-03 KST  
대상 브랜치: `commercial/wall-physics-qa`

이 문서는 외부 작업 지시 원문을 저장소의 실행 기준으로 요약한 문서다. 목표는 앱스토어 출품 자체가 아니라, 현재 4단계 수직형 데모가 실제 모바일 게임처럼 이해 가능하고 안정적이며 확장 가능한지 검증하는 것이다.

## 완료 조건

- P0·P1 결함 0건
- 네 단계 모두 진입·클리어 가능
- 전 스테이지 소프트락·필드 이탈·무한 충돌 0건
- 동일 입력의 결정론 이벤트 스트림 불일치 0건
- 벽 이동 0건
- 이전 공도 새 공과 충돌하고 홀 클리어에 참여
- 뾰족함·풍선 경로와 무속성 우회 경로가 모두 유지
- 앱 재실행 뒤 진행·별점·보상·복제 코어 복원
- 한글 UI 잘림·영문 임시 문구·디버그 문자열 0건
- Web과 모바일에서 핵심 판정 결과 일치
- 실제 기기·플레이테스트 결과와 자동 검증 결과를 분리 기록

실제 사용자 80%의 30초 내 조작 시작, 70%의 1단계 인과 설명, 4단계 경로 발견률, iPhone 12급 60FPS는 자동 테스트로 대체하지 않고 실험 결과가 확보될 때까지 미검증으로 표시한다.

## 고정 원칙

1. 물리 판정은 순수 Dart `ShotResolver`가 확정한다.
2. Flame은 확정된 상태와 충돌 이벤트를 재생하며 판정을 변경하지 않는다.
3. 벽은 모든 연쇄 충돌에서 고정이다.
4. 충돌 대상의 타입·질량·재질·법선을 후속 판정에 반영한다.
5. 이전에 발사된 공도 필드의 물리 객체다.
6. 홀 도달 자체가 기본 성공 조건이다.
7. 특정 속성·스위치·문·풍선 사용을 유일한 정답으로 강제하지 않는다.
8. 모든 사용자 노출 문구는 한글이다.
9. 탑뷰만 유지하며 쿼터뷰·회전·3D 전환을 추가하지 않는다.
10. 온라인 계정·리더보드·결제·광고·클라우드 저장은 범위에서 제외한다.

## 실행 단계

### 0. 기준선

- 브랜치·원격·작업 트리 확인
- 전체 테스트 결과와 Web 번들 체크섬 기록
- `tool/baseline_snapshot.dart`로 네 단계 초기 상태 스냅샷 생성
- 대표 성공·실패 리플레이와 물리 이벤트 예시 추가
- 저장 키·버전·마이그레이션 규칙 고정
- 과거 문서의 단계 수·테스트 수를 최신 기준으로 갱신

### 1. 물리·결정론

- 단일샷·다중샷·속성별 리플레이 반복 검증
- 벽 불변성, 공·공 충돌, 접선·모서리·고속 충돌 검증
- 상자·돌·젤리·풍선·점착판의 후속 충돌 검증
- 홀 경계·홀 선행 포획·홀 진입 후 후속 이동 차단 검증
- 반복 충돌·침투·미세 진동·안전 중단을 진단 이벤트로 남김
- 30·60·120Hz에서 물리 이벤트 순서와 애니메이션 순서를 비교

### 2. 조작·튜토리얼

- 최소 개입형·행동 유도형·무설명 기준군을 디버그 빌드에서 선택
- 물체 선택, 속성 이전·복사, 방향 조정, 길게 누르기, 손 떼기 발사의 이해도 계측
- 정답 궤적·강제 기믹·실패 직후 정답 노출은 금지

### 3. 퍼즐·난이도

각 성공 입력을 `recommended`, `alternate`, `direct`, `exploit`로 분류한다.

- 1단계: 무거운 공의 질량·상자 이동 차이
- 2단계: 충돌면 법선·반사각
- 3단계: 스위치·문·점착의 인과와 우회
- 4단계: 뾰족함 터뜨리기·일반 공 반사·무속성 우회

추천 경로와 우회 경로가 함께 있어야 통과하며, exploit가 가장 쉽거나 유일한 성공 경로가 되면 수정한다.

### 4. 표현 품질

- 공·상자·돌·젤리·풍선의 재질별 압축·기울기·구름·잔상
- 충돌 위치와 VFX 위치 일치
- 발사·충돌·속성 이전·소모·스위치·문·풍선·홀의 사운드와 햅틱 동기화
- 저모션·화면 흔들림 끄기·사운드·햅틱 설정 제공

### 5. 기기·성능

- iPhone 12급, iPad Pro, 소형·중급 Android, Chrome·Safari Web 확인
- 60FPS 평균, p95 16.7ms, p99 25ms를 목표로 기록
- Safe Area, 터치 좌표, 팝업, 지도 카드 자동 배치 확인
- 10개 공·10개 이동 물체·30개 충돌·빠른 재시도 스트레스 테스트

### 6. 저장·복구

핵심 저장 키는 다음과 같다.

```text
property_shot_cleared_levels
property_shot_unlocked_level
unlocked_level
property_shot_save_version
best_shots_level_<stage>
bonus_goal_level_<stage>
property_shot_copy_core_count
property_shot_copy_core_rewarded
```

신규 설치, 단계별 클리어, 손상 문자열, 중복 값, 구버전 키, 키 충돌, 강제 종료, 클리어 팝업 중 종료, 복제 코어 사용 직후 종료를 검증한다. 마이그레이션은 멱등적이어야 하며 구버전 키는 즉시 삭제하지 않는다.

### 7. 최종 판정

- 기능·물리·UX·콘텐츠·표현·기술 게이트를 각각 판정
- 자동 테스트, Web, 실기기, 사용자 테스트의 증거를 구분
- 모든 필수 게이트 통과 시 `Go`
- P2 폴리싱 또는 제한 기기 보완만 남으면 `Conditional Go`
- 핵심 인과·물리·저장·입력 문제가 남으면 `No-Go`
